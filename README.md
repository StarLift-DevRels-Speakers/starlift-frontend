# StarLift — фронтенд

SPA на React. Данные хранятся на бэкенде ([starlift-backend](https://github.com/StarLift-DevRels-Speakers/starlift-backend)),
API по умолчанию доступен по адресу `https://startlift.duckdns.org/api`. Подписки, тестовые покупки и AI-подбор пока остаются демо: они хранятся
в `localStorage` браузера отдельно для каждого пользователя.

```bash
yarn          # установить зависимости
yarn dev      # dev-сервер на http://127.0.0.1:5173
yarn build    # проверка типов и сборка
yarn lint     # ESLint
```

## Лендинг

Корень сайта `/` — публичная продающая страница: она открывается без входа, а кабинеты `/speaker` и `/devrel`
по-прежнему требуют авторизации. Страница идёт по разделам: первый экран с бейджем и «сценой» из парящих карточек,
блок «Спикерам» (AI-продюсер, AI-подбор мероприятий, анализ речи), блок «Мероприятия» с ближайшими событиями
и открытыми CFP, блок «DevRel» (каталог спикеров, AI-подбор спикеров, аналитика программы), затем тарифы
и тёмный финальный призыв. Фон украшают размытые градиентные пятна из палитры, карточки при этом остаются
однотонными. Отзывов и лиги на лендинге нет. Порядок и тексты лежат в `src/features/landing/content.ts`,
сроки CFP считаются в `src/features/landing/events.ts`, компоненты — в `src/components/landing/`.

Цены в блоке тарифов собираются из `src/features/billing/pricing.ts` (`subscriptions`, `roleRights`, `rightPrices`,
`formatRub`), поэтому меняются вместе с кабинетом и не дублируются в разметке лендинга. Планов три: бесплатный
уровень для обеих ролей и две подписки; рекомендуемый план выделен контуром без текстовой метки.

Кнопки ведут на `/login` (вход) и `/login?mode=register` (регистрация); кнопка «Подать заявку» в блоке мероприятий
всегда ведёт на регистрацию. В демо-режиме дополнительно появляются ссылки «спикер» и «DevRel» — они открывают
кабинет сразу, без формы. Шапка и подвал лендинга используют ту же палитру `--sl-masthead`, что и верхняя панель
платформы, а карточки блоков стоят на однотонной поверхности без градиентов.

## Деморежим для работы над дизайном

Создайте `.env.local` в корне проекта:

```env
VITE_DEMO_MODE=true
```

Запустите `yarn dev` (или `npm run dev`) и откройте `/speaker` либо `/devrel`.
Вход и бэкенд не нужны. Кнопка «Демо: DevRel / Спикер» в шапке переключает роль.
Данные каталогов, профилей, мероприятий, заявок, отзывов и рейтинга подставляются локально;
формы меняют демоданные в браузере. Это сценарии для проверки интерфейса, а не полная имитация проверок бэкенда.

### Путь в демо через лендинг

1. Откройте `/` — это лендинг, он доступен без входа.
2. «Войти» или «Создать аккаунт» ведут на `/login`. В деморежиме форма не требует логина и пароля:
   выберите роль «Спикер» или «DevRel» и нажмите «Открыть демо».
3. Ссылки «спикер» и «DevRel» на лендинге открывают кабинет сразу, без формы.
   Они делают полную перезагрузку страницы: демо-роль читается из адреса (`/speaker` или `/devrel`).
4. Вернуться на лендинг можно по адресу `/` или по логотипу на странице входа.

После правок `src/app/router.tsx`, `src/auth/AuthProvider.tsx` и `src/auth/authContext.ts` нужна жёсткая
перезагрузка страницы (Ctrl+Shift+R): Fast Refresh изменения роутера и провайдера не применяет.

По умолчанию у спикера есть доклады, выступления и отзывы, а у DevRel есть черновик, опубликованные
мероприятия и входящие заявки. Для проверки нового спикера добавьте `VITE_DEMO_SCENARIO=empty`
в `.env.local` и перезапустите Vite.

Для сброса данных удалите в DevTools → Application → Local Storage ключ `starlift-design-demo-v1`
(или `starlift-design-demo-empty-v1` для пустого сценария) и обновите страницу.
Тестовые покупки можно сбросить отдельно в разделе «Подписка и покупки».
Формы отзыва по демоссылкам работают в том же браузере.

Чтобы вернуться к бэкенду, установите `VITE_DEMO_MODE=false` и перезапустите dev-сервер.
В production-сборке деморежим всегда отключён.

## Запуск вместе с бэкендом

Dev-сервер проксирует `/api` на `https://startlift.duckdns.org`. Для работы с локальным бэкендом
задайте переменную окружения `VITE_API_PROXY=http://localhost:8080` перед запуском Vite:

```bash
# в starlift-backend
docker compose up -d postgres minio minio-init redis
mvn spring-boot:run

# здесь
yarn dev
```

Вход — на `/login`. Регистрация создает аккаунт Спикера; роль DevRel выдает администратор
(`PATCH /api/users/{id}/role`). Пользователи с ролями `DEVREL` и `ADMIN` работают в разделе `/devrel`, остальные — в `/speaker`.

Публичная форма отзыва (`/feedback/<token>`) открывается без входа: ссылку на нее Спикер получает для каждого
выступления на странице «Отзывы».

## Анализ речи

Для запуска всего локального стенда на Mac выполните в соседнем репозитории
бэкенда `./tools/audio-analysis/local.sh up`. Он поднимает Docker-сервисы
и нативный аудиоворкер; приложение доступно на http://localhost:5174.
В этом режиме запросы `/api` идут в локальный бэкенд.

В разделе спикера «Медиа» загрузите MP3, WAV, OGG или M4A и нажмите
«Анализировать речь». Запись должна быть на русском, без видео, до 50 МБ
и 60 минут; основной сценарий — один спикер. Статус обновляется в фоне,
отчёт можно открыть после перезагрузки страницы. Повторный запуск доступен
после завершения задачи.

В отчёте есть плеер, расшифровка, темп, паузы и кандидаты в слова-паразиты,
повторы и текстовые заминки. Нажатие на таймкод включает нужный фрагмент.
Старые отчёты без таймкодов слов используют время сегмента. Находки требуют
проверки контекста; смысловой разбор Qwen в этот интерфейс не подключён.

Нужен бэкенд с `GET/POST /api/audio-analyses`, `GET /api/audio-analyses/{id}`
и запущенный Python-воркер с моделями. Настройка воркера описана в
`tools/audio-analysis/README.md` бэкенда. В деморежиме запросы анализа
не отправляются на сервер; интерфейс сообщает, что обработка недоступна.

## Деплой (Docker)

Адрес API задаётся при сборке через `--build-arg VITE_API_BASE_URL=...`.
Пустое значение включает запросы к текущему домену; тогда сервер должен
проксировать `/api` в бэкенд (локальный Compose уже это делает).

Образ собирает проект в Node и отдает готовую статику через nginx (`deploy/nginx.conf`):

```bash
docker build -t starlift-front .
docker run -d -p 8080:80 --name starlift-front starlift-front   # http://localhost:8080
```

Любой адрес приложения (`/speaker/...`, `/feedback/<token>`) отдает `index.html`, маршрут разбирает react-router.
В production-сборке браузер обращается к `https://startlift.duckdns.org/api`. Чтобы сменить адрес,
задайте `VITE_API_BASE_URL` при сборке. Для запросов через тот же домен укажите пустое значение
и настройте проксирование `/api` на сервере.
